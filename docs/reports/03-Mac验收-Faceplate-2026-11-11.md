## 一、结论

1. 界面在 Mac 上能用，真录了三段，文件是 HEVC ＋ AAC，摄像头小窗和麦克风声音都进了成品。
2. 发现并修了三个 Mac 独有的问题（分支 `mac/faceplate-fixes`）：三个窗口按钮压在面板圆角上；窗口不能用鼠标拖动；面板上屏幕名显示成 “Capture screen 0”。

## 五、没修的问题

1. **Mac 上红点键永远弹选择框（f）。** 共用逻辑，而且是有意的设计，改它等于改产品行为，不是 Mac 独有的毛病。建议：只有一块屏幕、有权限、上次选的不是“单个窗口”时直接开始。等 Gabriel 定。
2. **“继续”有一次没接上（g）。** 第一段录像暂停后点“继续”，录制条一直显示“已暂停”，清单里第 1 段写了开始时间但没有 `seg-001.mp4`，辅助进程已经不在；停止后成品只有第 0 段。之后又试了两次（包括“继续后立刻收起预览”）都正常，没能复现。应用的错误输出是空的，原因没查明。这会丢内容，应该单独开任务查：先让 `resume()` 失败时把原因写进日志并提示用户。
3. **麦克风下拉框文字截断（j）。** 下拉框宽 130 px 放不下“跟随系统（设备名）”。Windows 上设备名一样长，不是 Mac 独有，留给界面的负责人。
4. **`cargo fmt --check` 不过。** `main` 上原有，见第二节。建议单独开一个只做格式化的 PR，在两边都没有在途分支的时候合。
5. 暂停时预览仍标“实时画面”；短录像提示“超出预算”。都是小问题，两个平台一样。

## 六、修了什么（`mac/faceplate-fixes`，基于 `shared/ui-faceplate`）

1. **能力标志 `overlayTitleBar`。** `types.rs` 和 `types.ts` 同时加，`Capabilities::of` 里只有 macOS 为真；模拟数据和默认值也补了。界面只看这个标志，不判断平台名。
2. **顶部空带（`Main.svelte`）。** 标志为真时，面板上方留 28 px，面板按剩下的高度整块缩放并下移；这条空带和面板外面的外壳带 `data-tauri-drag-region`，用来拖窗口。标志为假（Windows）时布局和原来逐像素一样，没有可拖动区域。默认窗口 1180×760 下面板缩到约 98%。
3. **屏幕名。** 面板原来只把 Windows 的设备路径（`\\.\DISPLAY1`）换成“屏幕 N”，现在 “Capture screen N” 也一样处理，和选择框里的叫法一致。
4. 测试新增 3 项（有空带且可拖、没有标志就没有空带、设备名换成“屏幕 1”），Rust 的能力测试补了新标志。`docs/PLATFORM-ARCHITECTURE.md` 的标志清单同步了。

## 七、过程里要知道的三件事

1. **为什么不用 `tauri dev` 验收。** `tauri dev` 起的程序没有应用包身份，系统把屏幕录制、摄像头权限算在启动它的那个程序头上，权限项没法验。所以项 a–m 都是在打出来的 `.app` 上看的。`npm run tauri dev` 本身能起来，Gabriel 确认看到了面板（日志 `10-tauri-dev.log`）。
2. **“授权了，重启又变回去”。** 系统记的屏幕录制授权绑在签名身份上。这台机器上原有的授权属于旧克隆（`../screen-recorder/.signing`）的自签名身份，而新克隆第一次跑 `build-mac.sh` 会新建一个身份，于是同一个应用名对应两个签名，开关打开了也不生效。处理：把旧克隆的 `.signing/` 复制到本仓库（git 忽略）再重新签名。换机器或重新克隆时要带上 `.signing/`，否则要重新授权。
3. **窗口被完全挡住时不会画出来。** `tauri dev` 起来后窗口如果被别的窗口完全盖住，截图是白的，点到前面一次就好。不是程序的毛病，但自动截图时容易误判。

## 八、哪几条最没把握

1. **拖动窗口修好了**：只有代码和单元测试，没有真拖成功的证据。验证：用鼠标按住窗口顶部那条空带拖。
2. **“继续”失败是偶发**：三次里一次，样本太小，不能说概率低。验证：连续暂停／继续 20 次，每次核对成品时长。
3. **缩放在所有尺寸下都对**：只看了三个尺寸，没看最小尺寸和 Retina；新加的顶部空带在最小尺寸下也没看。验证：把窗口缩到最小，再拖到笔记本自带屏幕上各看一眼。
