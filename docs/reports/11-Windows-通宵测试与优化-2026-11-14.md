# 11 · Windows 通宵：下一轮的 Windows 平台层、全面实测、性能优化

- 日期：2026-11-13 夜到 2026-11-14 凌晨，无人值守。作者：Claude（Windows 负责人）。分支：`win/overnight-2026-11-13`（基于 Mac 的 `mac/next-round`），草稿 PR。
- 证据都在 `tests/out/overnight/`（已被 git 忽略），下文写的文件名都相对这个目录。微软文档原文在 `tests/out/next-round/sources/`。
- 级别：**A** 本机命令输出、截图或微软原文；**D** 我的推断。核实日期都是 2026-11-14。
- 测试机：Windows 11，Intel 核显，一块 3840×2160 屏幕，USB 摄像头“2K USB Camera”，USB 麦克风“Fifine”。测试时同一台机器上另一个 Claude 会话在给整个硬盘算哈希，机器很忙，数字偏保守。

## 1. 结论

Mac 那边写好的下一轮（滚动截图、4K、开机启动、四个快捷键、新图标）在 Windows 上编译、测试全过；我补上了 Windows 的平台层，并在普通版和上架版（有包身份）里都实测过。测的过程中找出并修了 7 个问题，其中 2 个是性能问题。

找到但**没修**、需要你决定的有 3 个：

1. **上架版用不了硬件编码**。包身份下，Intel 显卡驱动自带的编码组件只要 ffmpeg 放在包目录里就崩溃（驱动的问题，不是我们的），应用自动退到软件 H.264，能录，但 CPU 多用约四分之一个核。修法见第 5 节第 1 条。
2. **声音和画面可能差几百毫秒到将近一秒**。麦克风和屏幕各用各的时钟，从 0 开始对齐。修之前，开着麦克风时声音比画面短 0.3–1.4 秒；把麦克风缓冲改小以后，1080p 降到 0.15–0.23 秒，但 4K 带摄像头仍差 0.97 秒。用真实声音测的那一步没做成：音箱的声音没进麦克风（麦克风输入音量只有 29%），要你在场测一次。
3. **上架版第一次用麦克风／摄像头时 Windows 会弹框问**。我按规矩没点。应用现在会告诉用户“Windows 在问”，而不是只说“无法开始录制”。

## 3. 实测结果

### 3.1 滚动截图

测法：我写了一个会自己滚动的窗口，里面是一张已知的长图（文字、色块、空白），截完和原图逐像素比。“错行”指一行里超过 2% 的像素对不上。

| 场景 | 开发版（修完后） | 上架版（有包身份） |
|---|---|---|
| 每 250 毫秒滚 120 像素，6000 行 | 6000 行，0 错行 | 6000 行，0 错行，完成用 0.58 秒 |
| 窗口顶上有不动的标题栏 | 6070 行，0 错行 | 6070 行，0 错行 |
| 慢滚（每次 20 像素） | 3000 行，0 错行 | — |
| 每 250 毫秒滚 300 像素 | 6000 行，0 错行（修前停在 2400 行且有错行） | 6000 行，0 错行 |
| 每 250 毫秒滚 600 像素 | 6000 行，0 错行 | — |
| 20000 行长页面 | 20000 行，0 错行 | 20000 行，0 错行，完成用 0.93 秒 |
| 一次滚一整屏（850／900） | 只有第一屏：接不上，提示往回滚 | — |
| 不停顿地快速滚（每秒 2500 像素以上） | 只有第一屏：画面一直不停，没有可用的帧；停下来往回滚一点就能接上 | — |

剪贴板里同时有 PNG 和位图，760 × 6000 `[A]`。

最后两行是有意的取舍：宁可短，不拼错。快速不停地滚时，撕裂帧和正常帧分不出来。

### 3.2 录制（开发版，第三方 ffmpeg，Intel QSV 硬件编码）

| 场景 | 结果 |
|---|---|
| 1080p，摄像头＋麦克风，暂停再继续 | 能录、能合并、全部帧可解码；**声音比画面短 1.3 秒，暂停处有 1.25 秒的声音空缺** |
| 4K（3840 宽）＋麦克风 | 3840×2160 HEVC，能录；声音短 0.33 秒 |
| 原始大小 60 帧 | 3840×2160 60 帧，无问题 |
| 720p 不带声音 | 无问题 |
| 1440p，圆形摄像头小窗在左上 | 能录；声音短 1.4 秒 |
| 两次暂停 | 能录；声音短 1.2 秒 |
| 用新快捷键开始、暂停、继续、停止 | 全部有效 |

修麦克风缓冲之后，在发布版里再录了三段 `[A · ../win-night/matrix.jsonl 的 R1–R3]`：

| 场景 | 声音比画面短 | 暂停处空缺 |
|---|---|---|
| 1080p，摄像头＋麦克风，暂停再继续 | 0.23 秒（修前 1.3 秒） | 0.97 秒（修前 1.25 秒） |
| 1080p，只有麦克风 | 0.15 秒（修前 0.33 秒，那段是 4K） | — |
| 4K，摄像头＋麦克风 | 0.97 秒 | — |

剩下的差和摄像头有关：几个输入是一个接一个打开的，摄像头最慢 `[D]`。

麦克风录到的平均音量在 −58 到 −82 dB：夜里房间是静的，加上麦克风输入音量只有 29% `[A · sync/device-levels.txt]`。所以“有没有录到人声”没有验证。

### 3.3 音画同步：没测成

我放了 6 声 1 kHz 的短“嘀”，同时在屏幕中间闪白块，然后用 `scripts/sync-check.ps1` 分析。结果白块找到 2–3 个，“嘀”只找到 1 个：声音没进麦克风。默认播放设备音量 100%、没静音，但看起来音箱没开或接的是耳机。我没改任何系统设置，这一项**未验证**。

时间戳上的事实 `[A]`：屏幕输入从 0 开始计时；麦克风用开机以来的时钟（`start: 168011.48`）；ffmpeg 把两边各自归零。所以两边的“0”不是同一刻，差值大约等于麦克风比屏幕晚打开的那段时间。把麦克风缓冲改小（问题 6）应该能缩小这个差，但没有测量。

硬件编码的查证过程 `[A]`：

- 系统事件日志写的是 `ffmpeg.exe` 崩在 `mfx_mft_h265ve_64.dll`（Intel 显卡驱动 26.8.7.5603 自带的编码组件），错误码 0xc0000005。
- 同一个 ffmpeg 文件（哈希相同），放在包目录**外**、以包身份运行：硬件编码正常。放在包目录**里**：崩溃。
- 第三方 ffmpeg 放进包目录里，结果一样：Media Foundation 硬件编码崩溃，**Intel QSV 正常**。
- 关掉注册表和文件重定向（`unvirtualizedResources`），仍然崩溃。

证据：`46-crash-matrix-in-package.txt`、`47-…unvirtualized.txt`、`48-qsv-in-package.txt`、`49-…`、`50-…`、`51-btbn-inside-package-folder.txt`。

### 3.5 性能（30 秒 1080p 录屏，CPU 按“一个核的百分比”算）

| | 开始录制要多久 | ffmpeg CPU | 界面进程 CPU | 界面进程内存 |
|---|---|---|---|---|
| 普通版，修之前 | 1.10 秒（不带麦克风） | 65%（QSV 硬件） | 31.5% | 728 MB |
| 上架版，修之前 | 1.06 秒 | 80%（软件 H.264） | 26.3% | 716 MB |
| 开发版，主窗口不再绘制 | 1.11 秒 | 62% | 11.2% | 566 MB |
| 再加卷盘交给显卡转 | 1.35 秒 | 61% | **9.7%** | 637 MB |

ffmpeg 大部分时间花在把 4K 画面从显卡拷到内存，再用 CPU 缩小。试过让显卡直接缩小（`scale_d3d11`），两个 ffmpeg 都报“不支持的像素格式”，没做成 `[A · perf/63-gpu-path.txt]`。ffmpeg 内存约 600 MB，和输入队列长短无关 `[A · perf/64-queue-memory.txt]`。

## 5. 没做到的和没验证的

1. **上架版的硬件编码**。三条路：
   - （甲）在我们自编的 ffmpeg 里加 Intel 的 VPL 库（MIT 许可，和 LGPL 兼容），让上架版走 QSV。只管 Intel 显卡；NVIDIA／AMD 的情况没测。
   - （乙）运行时把 ffmpeg 复制到包目录外再运行。实测能用，但复制出来的文件不带商店签名，智能应用控制可能会拦，商店审核也可能有意见。
   - （丙）维持软件编码。

   我建议甲，要你点头，因为要改 ffmpeg 构建和许可文件。
2. **音画同步**：没有用真实声音测过（3.3）。下一步的修法 `[D]`：让屏幕和麦克风用同一个时钟。麦克风已经可以按到达时间打时间戳；屏幕输入（`ddagrab`）要在滤镜里换成墙上时钟，再统一起点。要先有第 6 节第 2 条的实测，才知道往哪边、改多少。
3. **开机后真的自动启动、而且不弹主窗口**：要注销再登录，没做。
4. **托盘图标和新的 MSIX 图标在任务栏、开始菜单里长什么样**：没截图；100%／150%／200% 缩放要改系统设置，没做。
5. **上架版录麦克风和摄像头**：卡在系统权限弹框，没测。
6. **显卡直接缩放**（性能的下一步）：没做成。
7. **普通安装包装上以后的样子**：没装。
8. 多显示器、不同缩放下的滚动截图：这台只有一块屏，没测。

## 6. 留给你的事

1. **决定上架版硬件编码走哪条路**（第 5 节第 1 条，建议甲）。
2. **测一次音画同步**，约 3 分钟：
   - 打开音箱，把麦克风输入音量调高（现在 29%）。
   - 开着麦克风录制，运行 `pwsh scripts/sync-signal.ps1`。
   - 停止，再运行 `pwsh scripts/sync-check.ps1 -File <录像>`。
3. **在上架版里回答一次麦克风和摄像头的权限弹框**。包已经注册好：开始菜单里的 FlowGT Recorder 就是它。之后录一段带声音的，听一下。
4. **注销再登录一次**：先在设置里打开“登录后自动启动”，回来后看应用是不是在托盘、没弹主窗口。
5. 看一眼托盘图标和任务栏图标好不好看。
6. 审 PR。它基于 Mac 的 `mac/next-round`，合并顺序是先合 Mac 的，再合这个。
7. 删掉今晚的测试文件：“视频\FlowGT Recorder”里 2026-11-14 开头的 24 段录像，`Screenshots` 里 2026-11-13／14 的 39 张截图。

## 7. 最没把握的三条

1. **“稳定”选项在真实浏览器里的手感**。测试窗口是我写的，滚动是一格一格跳的；浏览器的平滑滚动会不会让画面迟迟停不下来、图拼得慢，没在真浏览器里测过。
2. **主窗口不绘制以后有没有副作用**。录完回到主窗口时，结果页和卷盘都正常显示（截图为证），但只在开发版里试过几次。
3. **Intel 驱动崩溃是不是只有这台机器、这个版本**。只有一台机器，一个驱动版本（26.8.7.5603）。
