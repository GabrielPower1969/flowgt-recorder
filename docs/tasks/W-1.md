## Result

rustc 1.99.1 (MSVC), Visual Studio Build Tools 2022 17.14 (MSVC 14.44, Windows SDK 10.0.26100),
WebView2 157.0.4341.42, ffmpeg n9.0.1 LGPL from `scripts/fetch-ffmpeg.ps1`.

All four checks are green **with three fixes applied together**. They live on three branches, so `main` plus
this branch alone is not green yet:

## Not verified

- **The `windows-latest` CI job has never run.** GitHub ended every job with "account is locked due to a billing
  issue". As written the workflow would also fail on both runners: it never puts the sidecars in
  `src-tauri/binaries/`. The fetch step is on `shared/ci-sidecars`, unverified.
- CI uses Node 22; these runs used Node 26. The `localStorage` fix is written to be a no-op on Node 22 but was
  not run there.
- None of the three code fixes was built or tested on macOS.
- `cargo fmt --all -- --check` fails on `main` in 17 files (long lines; the tree was never run through
  rustfmt). It is not one of this card's checks and not in CI. Left alone.
- `npm install` warned that esbuild's install script is not on the allow list (npm 11). The tests and the dev
  server ran anyway.
