## Result

Done on the Windows test machine, where the missing flags showed: the recording window carried an empty
"Waiting for the first frame…" panel for the whole recording.

- `Capabilities` in `types.rs` and `types.ts` (same commit), with the ten flags of
  `docs/PLATFORM-ARCHITECTURE.md` section 6, and the pure rule
  `Capabilities::of(platform, native_engine, system_audio)`: window capture and the live preview exist only
  with a native capture engine.
- A new command `get_capabilities`. It starts no ffmpeg, unlike `get_app_info`, so the UI has its answer
  before the user can open anything. `AppInfo` is unchanged.
- `src/lib/stores/capabilities.svelte.ts`, loaded once in `App.svelte`. Inside the app nothing optional is
  offered until the backend answers; the browser preview and the tests start from the mock (a Mac with the helper).
- `ScreenPicker`: the window tab follows `windowCapture` (was `getPlatform() === "macos"`).
- `Floating`: the preview panel and its toggle follow `livePreview`; `windows.rs` sizes the window as the bar
  when there is no live preview.

## Not verified

- **macOS.** With the helper present every flag equals today's behaviour by construction, and the mock-based
  tests pass, but nothing was built or run on a Mac. One intended difference: a Mac **without** the helper no
  longer shows the window tab (it showed a tab with an empty list).
- `systemAudio` is reported but not consumed yet: `Main.svelte` still reads `AppInfo.systemAudioAvailable` and
  the loopback list. `camera`, `tray`, `globalShortcuts`, `pauseResume`, `floatingBar`, `pictureInPicture`
  and `perAppAudio` are reported and have no reader yet.
- The moment between window creation and the backend's answer: inside the app the optional controls are hidden
  until then. Not timed.
